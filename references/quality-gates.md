# 标注质量门禁

通过对比原图、`mask-visualization.png`、`bbox-visualization.png`，并结合 `annotations.json`，对初次标注质量进行评价。评价分两步：先做整体扫描判断实例是否漏标，再对每个已标注实例逐个评估并赋予标签。

## 一、整体评价

先从全局判断标注完整性，不要一开始就陷入单个实例的细节。

### 1.1 实例漏标检查

- 逐类别核对：原图中每个类别的可见实例是否都已被标注。COCO 实例总数必须等于原图可见实例总数。
- 实例级标注文件必须提取且只提取一个红色实例。
- 接触实例不能通过侵蚀、人工留缝或连通域切割伪分离；若出现此类伪分离，按对应实例重新标注。

### 1.2 漏标定位

发现漏标时，为后续补充标注提供定位信息：

- 位置：漏标实例在原图中的大致区域（如左上、画面中央、右下），尽量结合图像坐标或相对已标实例的方位描述。
- 特征：漏标实例的类别、外观特征（颜色、朝向、遮挡程度），以及与已标实例的空间关系。
- 补充建议：建议用类别级还是实例级模式补充；若与已标实例接触或重叠，必须使用实例级模式，且以同一张未标注原图为输入。

## 二、逐实例评估

对每个已标注实例，使用默认半透明 mask 图同时观察原图边缘与红色掩码边缘——不要仅凭完全不透明填充判断对齐质量。从下表五个标签中选择最贴切的一个；若同时存在多种问题，按最严重者归类，并在备注中记录次要问题。

| 标签 | 定义 |
|------|------|
| 标注合格 | 掩码完全贴合实例真实边界，无需调整修改 |
| 多标 | 背景或其他类别被错误标注 |
| 边界偏移 | 掩码相对对象整体发生平移或缩放 |
| 掩码不足 | 对象边缘、椅腿、枕头角等被截断 |
| 掩码溢出 | 掩码覆盖背景、阴影或邻近对象 |

## 三、各标签判断标准与依据

### 3.1 标注合格

- 判断标准：掩码沿实例真实可见轮廓贴合，无系统性偏移、无截断、无溢出、无误标区域。
- 判断依据：
  - 半透明 mask 边缘与原图对象边缘各处重合，肉眼无明显错位（通常 1–2 像素以内）。
  - 对象细部（椅腿、把手、枕头角、孔洞等）均被完整覆盖，未丢失。
  - bbox 为 mask 的最小外接轴对齐矩形，`area` 等于映射后二值 mask 像素数，polygon 非退化。

### 3.2 多标

- 判断标准：掩码覆盖了不属于该实例的区域，对象本身被错误地纳入或连入标注。
- 判断依据：
  - 红色区域延伸到相邻的不同类别对象，或把本应分离的多个独立实例连成一片。
  - 掩码面积明显大于对象可见投影面积，且多出部分构成可辨识的其它对象或区域。
  - 与“掩码溢出”的区别：多标是对象级错误（标错了对象/类别），溢出是边界级错误（对象对了，边缘画大了）。

### 3.3 边界偏移

- 判断标准：掩码形状与对象大致吻合，但整体相对对象发生了平移或缩放。
- 判断依据：
  - 一侧边缘内缩、对侧外扩，呈系统性方向偏移（平移型）。
  - 掩码整体大于或小于对象，但各处比例一致（缩放型）。
  - 常伴随配准指标异常（内点比例低、重投影误差大）或局部修正触达搜索边界。

### 3.4 掩码不足

- 判断标准：对象部分可见区域未被掩码覆盖，边缘或细部被截断。
- 判断依据：
  - 对象真实边缘落在 mask 之外，可见区域出现留白。
  - 细长或凸出结构（椅腿、桌脚、枕头角、把手）缺失或被截短。
  - `area` 明显小于对象可见投影面积。

### 3.5 掩码溢出

- 判断标准：掩码超出对象真实边界，侵入周围背景、阴影或邻近对象。
- 判断依据：
  - 红色边缘越过对象真实轮廓，覆盖周围背景或阴影。
  - 与相邻实例接触处越过本实例边界，覆盖对方区域。
  - 与“多标”的区别：溢出仍是同一实例的过度延伸，对象本身识别正确。

## 四、数据一致性检查

无论赋予何种标签，以下硬性要求必须满足：

- bbox 必须是 mask 的最小外接轴对齐矩形。
- `area` 必须等于映射后二值 mask 像素数。
- polygon 不得为空或退化。

## 五、结构化质量报告

- 必须使用 `quality-report.example.json` 的结构；每个已标注实例对应一个 `annotation_id`，每个漏标实例使用独立的 `instance_key` 且 `annotation_id=null`。
- `description` 记录可辨识外观，`location.region` 和 `location.approx_center` 记录大致位置；禁止只写“有问题”。
- 初检结果写入 `initial_evaluation`。合格实例的 `retry.attempted=false`，后续不得重新生成或替换。
- 不合格实例若重标，必须设置 `retry_count=1` 并保存单实例标注图路径。一次重标后的评价写入 `final_evaluation`。
- 未重标实例的 `final_evaluation` 保持 `null`，其最终评价沿用初检；重标一次仍失败的实例必须保留失败标签与证据，不得再次重标。

## 六、重做策略

只重做失败实例（多标、边界偏移、掩码不足、掩码溢出，以及漏标实例），仍以原图为输入。每个失败实例最多重标一次；使用 `quality_cycle.py apply` 定向替换对应 annotation，不能重建或扰动合格实例。重标后再次生成两张可视化并仅复核被替换/补充项。不得手绘大致多边形替代 image2 结果，不得通过侵蚀制造实例间隙；一次重标后仍有问题时必须如实交付失败评价。
